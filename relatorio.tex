\section*{1. Como executar e gerar o build estático}
O projeto usa Next.js 16 (App Router), React 19 e CSS Modules. É preciso ter o Node.js instalado.
\begin{itemize}
    \item \texttt{npm install} na raiz do projeto para instalar as dependências.
    \item \texttt{npm run dev} e abrir \url{http://localhost:3000} para rodar em modo de desenvolvimento.
    \item \texttt{npm run build} para gerar o site estático. Como o \texttt{next.config.mjs} tem \texttt{output: "export"}, os arquivos ficam na pasta \texttt{out/}.
    \item \texttt{npx serve out} para servir a pasta \texttt{out/} localmente e testar o build.
\end{itemize}

\section*{2. API externa}
Usamos a API REST da Wikipédia em português, que é pública e não precisa de chave:
\texttt{https://pt.wikipedia.org/api/rest\_v1/page/summary/\{página\}}.
Cada roteiro tem o campo \texttt{paginaWikipedia} no JSON, e o componente \texttt{QuadroWikipedia} faz o \texttt{fetch} dentro de um \texttt{useEffect}. Enquanto a resposta não chega aparece uma mensagem de carregamento; se der certo, mostramos o resumo e um link para o artigo; se a requisição falhar (sem internet ou status de erro), aparece um aviso dizendo que o texto de apoio não carregou. Como o quadro fica no fim da página e é carregado no navegador, o resto do roteiro aparece normalmente mesmo quando a API falha.

\section*{4. Mudanças em relação ao plano e ao protótipo}
\begin{itemize}
    \item \textbf{Cronograma:} as etapas 4 a 11 ficaram todas para o dia 23/10, porque o Pedro conseguiu fazer tudo de uma vez. Com isso sobrou o dia 24/10 para revisar, testar o build e escrever o relatório.
    \item \textbf{Opção ``Todos'' nos filtros:} no protótipo o filtro de ano só tinha 6º a 9º ano. Colocamos ``Todos'' (e ``Todas'' na disciplina) para o aluno poder ver todos os roteiros sem escolher um ano.
    \item \textbf{Roteiro inexistente:} a primeira versão gerava uma página fixa para o id \texttt{999} só para testar. Trocamos por \texttt{dynamicParams = false} com \texttt{notFound()} e uma página \texttt{not-found.js}, que vira o \texttt{404.html} do build. Assim qualquer id que não existe mostra a mensagem de roteiro não encontrado.
    \item \textbf{Validação do formulário:} usamos \texttt{noValidate} no \texttt{<form>} para o navegador não mostrar os balões dele, e listamos todos os erros juntos numa caixa abaixo do botão.
    \item \textbf{\texttt{suppressHydrationWarning} no \texttt{<body>}:} uma extensão do navegador (ColorZilla) adicionava atributos no \texttt{<body>} e gerava aviso de hidratação no modo de desenvolvimento.
\end{itemize}
